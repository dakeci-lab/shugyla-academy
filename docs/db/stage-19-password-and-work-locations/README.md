# Этап 19 — колонка `academy_users.password` и таблица `platform_work_locations`

## Почему можно удалять

- **`password`**: вход идёт через Supabase Auth (`auth.users`), пароль сотруднику задаёт Edge Function и хранит Auth.
  Колонка — остаток домиграционной схемы. На проде в ней были короткие значения в **открытом виде** (не хеш) у 2 из 3 записей —
  это риск, а не функция. Проверено: нет представлений, функций, политик, ограничений, индексов, прав для `authenticated`/`anon`;
  в коде единственные обращения — устаревшее сравнение пароля в `supabaseDataAdapter.authenticateUser` (не вызывалось) и запись
  при создании/правке сотрудника напрямую через клиент (Edge-путь пароль в колонку не пишет).
- **`platform_work_locations`**: после этапа 18 на таблицу не ссылается ни один внешний ключ, функций и представлений нет; точка
  работы использовалась графиком/сменами (удалены в 13d).

## Порядок

1. Код без `password` (PR этапа 19): адаптер данных, список выбора функции обновления сотрудника.
2. БД (`apply_19.sql`): `alter table academy_users drop column password; drop table platform_work_locations;`
3. Смена паролей: **пароли, лежавшие открытым текстом, нужно считать скомпрометированными** — сменить через «Сбросить пароль».
