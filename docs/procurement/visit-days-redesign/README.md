# Закуп по дням визита поставщиков (вместо норм по категориям)

Дата: 2026-10-25 · Статус: решения владельца приняты, реализация по шагам ниже.

## Зачем

Сегодня рекомендация считается как `продажа в день × норма категории − остаток`, а шкала «Точно / Перезатарка / Недостаток»
сравнивает запас с нормой ±20%. Дни заказа и доставки поставщика в расчёте не участвуют. Замер на снимке 2026-10-25:

- шкала: 9% «точно», 44% «недостаток», 48% «перезатарка» (по товарам с продажами);
- средняя норма 21,4 дня, а по графику поставщиков нужно около 8 (136 из 148 поставщиков с днями ездят раз в неделю, доставка в среднем
  через 1,4 дня);
- у 853 товаров запаса меньше срока доставки — закончатся раньше поставки;
- рекомендация не вычитает уже заказанное, но ещё не привезённое;
- в нормах две явные ошибки: «Станки и лезвия мужские» = 1330 дней, «Канцелярские принадлежности» = 450.

## Решения владельца

1. **День визита = день заказа** (`order_days`, когда торговый представитель принимает заказ); **день доставки** (`delivery_days`) — срок:
   когда товар должен поступить.
2. **Цель запаса** = `(дата доставки − сегодня) + цикл до следующей поставки + страховые дни`.
   Рекомендация = `продажа в день × цель − остаток − «в пути»`.
3. **Страховой запас — 1 день по умолчанию**, закупщик меняет на текущий заказ. Переключатель «пропускаем визит» прибавляет 7 дней
   (цикл на неделю вперёд), если торговый представитель сообщил, что на этой неделе приедет один раз.
4. **Поставщик без дней**: заказ формируется, цикл 7 дней, с пометкой «дни не заполнены, цикл 7 дней». Нормы как запасной вариант не используются.
5. **«В пути»**: заказ считается «в пути» от создания до конца даты доставки (по `expected_delivery_date`). После — считаем, что товар
   в остатках UMAG. Статусы приёмки не используются (504 из 511 заказов за 60 дней висят в «ждёт приёмки»).
6. **Нормы удаляются полностью** (вкладка «Нормы», правила, журнал, право `procurement.norms.manage`, `set_norm`, колонка `reserve_status`).
   Копия 100 правил: `norm-rules-backup-2026-10-25.csv`.
7. **Сразу новая шкала**, без теневого режима; перед запуском — один пересчёт последнего снимка для проверки. Старые снимки не пересчитываются.
8. **Минимальная сумма заказа** (`min_order_amount` в карточке; пусто = минимума нет): в планировании показывать
   «до минимума не хватает X ₸». Не блокирует.
9. **Дата доставки отдельно для каждого поставщика** (сейчас одна на все выбранные заказы); по умолчанию — ближайший день доставки из карточки.
10. Средняя продажа: не учитывать недели до появления товара, больший вес последним 4 неделям. Исключение дней без остатка — по ежедневным
    снимкам, если их глубина позволяет (проверить).
11. Скоропортящиеся категории (верхний предел) — **не в первой версии**. «Заказывать сегодня» — уже есть («Сегодня · N»), доработать.

## Дни недели, а не числа месяца

Код хранит дни недели (`["tue","fri"]`) и сам превращает их в ближайшие реальные даты. Ограничения: график «раз в две недели» днями недели
не выразить, праздники сдвигают поставки — оба случая закрываются правкой даты и «пропуском визита» в конкретном заказе.

## План (каждый шаг — отдельный PR; БД — этапами с preflight / postcheck / откатом)

1. **Подготовка данных.** Заполнить дни у поставщиков (`suppliers-to-fill.md`), мелкие и служебные (списания, ревизия…) не заполнять,
   а пометить так, чтобы они не мешали. Быстрая правка дней в карточке и в планировании. Валидация.
2. **Расчёт.** Чистые функции цели/цикла/«в пути» + тесты; пересчёт последнего снимка для проверки владельцем.
3. **База и функции.** Этап БД: снимок хранит `target_days`, `cycle_days`, `lead_days`, `in_transit_qty`; замена `reserve_status`;
   правка `umag-procurement` (деплой вручную через workflow).
4. **Планировщик.** Новая шкала, рекомендация, пометка «дни не заполнены», переключатель «пропускаем визит», страховые дни на заказ,
   дата доставки по каждому поставщику, подсказка по минимальной сумме.
5. **Удаление норм.** Вкладка, сервисы, правила, журнал, право, функции БД (без CASCADE, одной транзакцией, по образцу stage 13d).

## Риски

| Риск | Что делаем |
|---|---|
| Дни у части поставщиков не заполнены | цикл 7 дней и видимая пометка; список на заполнение |
| Поставщик не приехал / отложил | страховые дни, ручная правка рекомендации, переключатель «пропускаем визит» |
| Поставка пришла раньше/позже даты | «в пути» по дате; не привезли — товар снова попадёт в рекомендацию |
| Утренний снимок остатков не видит дневную поставку | «в пути» считается до конца даты доставки включительно |
| Удаление норм необратимо | копия правил в этом каталоге; откат БД — через этап |
| Новые сотрудники закупа привыкли к старой шкале | сразу новая шкала, пояснение в интерфейсе |
