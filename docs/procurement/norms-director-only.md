# Нормы запаса — менять может только директор

Дата: 2026-10-17 · Этап 16a

## Зачем

Шкала «Соответствие норме запаса» в «Закупках → Планирование» считается **заново при каждом открытии** по
текущим нормам (`get_procurement_snapshot_stock_health`: недостаток < 80% нормы, «точно» 80–120%, перезатарка > 120%;
цель владельца — 80% «точно», ≤10% перезатарки, ≤10% недостатка). По этой шкале оценивается закупщик. Пока нормы мог
менять сам закупщик (`procurement.edit`), это был конфликт интересов.

Оценка риска на живых данных (снимок 17.10, 7 258 товаров со спросом): «точно» сейчас 8,6%. Если идеально подобрать
норму каждой подкатегории — максимум 20,0%; каждой категории — 14,8%; сдвиг всех норм на +25%/×1,5 почти ничего не
меняет (9,1% / 8,7%). То есть сегодня нормами шкалу к цели не вытянуть, но потолок +11 п.п. есть и вырастет, когда
реальный запас приблизится к цели.

## Что сделано

- Новое право **`procurement.norms.manage`** («Управление нормами запаса»), выдано только роли `admin` (Директор).
  Миграция `20261017180000_procurement_norms_manage_permission.sql` (применена на проде).
- Edge Function `umag-procurement`: действие `set_norm` требует это право (раньше `procurement.edit`);
  `sync` и `generate` не менялись.
- «Закупки → Нормы»: ввод доступен только при праве; у остальных иконка замка «Нормы может менять только директор».
- Прямых путей обойти нет (проверено): таблица `procurement_norm_rules` без прав записи для `authenticated`, процедура
  `set_procurement_norm_rule_for_snapshot` недоступна `anon`/`authenticated`, `procurement_snapshot_items` обновляет
  только `final_order_qty`, `manual_override`, `updated_at`.

## Порядок выкладки (чтобы не заблокировать директора)

1. Право в БД и выдача директору (сделано до фронтенда).
2. Фронтенд (кнопки закрыты у остальных, у директора работают).
3. Edge Function (сервер начинает требовать право).

## Не сделано (следующие шаги)

- Журнал изменений норм (кто, когда, было → стало) — сейчас хранится только последний редактор.
- Атомарная смена нормы категории: сейчас БД перезаписывает все товары категории, а браузер по одному возвращает
  нормы подкатегорий (при обрыве часть подкатегорий в текущем снимке временно получает норму категории до
  следующей синхронизации).
- Методика премии: считать месячный итог по зафиксированным дневным значениям, а не «снимок момента» (решение владельца).

## Откат

```sql
delete from public.role_permissions rp using public.permissions p
 where p.id = rp.permission_id and p.code = 'procurement.norms.manage';
```
и вернуть предыдущую версию Edge Function.
