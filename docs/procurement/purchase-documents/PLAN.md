# «Закуп» как документы — план реализации (одобрен прототип, 2026-10-29)

Прототип: https://claude.ai/artifact/QkfXKkNgBUy6ed2hpyj3zx (версия 14). Решения владельца — в `README.md`; этот файл — этапы.

## Принципы
- **Старое работает, пока новое не готово.** Новые страницы строятся на новых адресах и подключаются в меню последним PR. Планирование (`/platform/procurement`) снимается после недели без жалоб.
- Один PR — одно направление; `verify:*` на каждый этап; документ этапа с откатом; удаления в БД выполняет владелец в SQL Editor, после каждого — поиск удалённых имён в телах функций (урок инцидента 25c).
- В интерфейсе только то, что реально работает (решение владельца: никаких «для красоты» кнопок).

## Что меняется по смыслу
- Заказ создаётся вручную в документе («+ Создать»), а не кнопкой «Создать заказ» из таблицы планирования. Планирование становится окном «Товары поставщика» внутри документа.
- Количества плана больше не «гасятся» при заказе: рекомендация считается от остатка и **в пути**, а «в пути» — сохранённые заказы. Поэтому повторного заказа тех же товаров не будет без пересчёта.
- Удаление черновика ничего не возвращает в план (возвращать нечего). Функции `generate_procurement_orders_from_snapshot` и правка итоговых количеств снимка становятся лишними (чистка — этап 8).

## Этапы
| № | Этап | Что входит | БД | Риск |
|---|---|---|---|---|
| 1 | **Номер документа** | колонка `number`, последовательность с 1001, выдача в «Сохранить» и при создании заказов из плана; нумерация уже сохранённых 939 заказов по дате создания; номер в списках, PDF/Excel, поиске | миграция (добавочная, через MCP) | дыр в нумерации нет: номер только при сохранении |
| 2 | **Страницы и меню** | меню «Закупки» без вкладок внутри страниц: «Закуп», «Заказы», «Расчёты», «Склад» — отдельные страницы со своими адресами; «Склад» выносится из «Закупа»; верхняя панель закреплена; общие стили: радиусы 4/6 px, статусы текстом и линией под суммой | нет | права: Закуп — `procurement.view`, Заказы — `receiving.view` |
| 3 | **Список «Закуп»** | таблица документов, период по умолчанию «Неделя», фильтр (создан / поставщик / статус / поиск по названию, штрихкоду, номеру), чип периода, итоги, страницы; черновик серым и линия под суммой; «+ Создать» создаёт черновик и открывает документ | нет | — |
| 4 | **Документ: шапка и таблица** | компактная шапка, выбор поставщика (вкладки «Сегодня · N» / «Все», поиск), дата доставки, комментарий окном, «Сохранить» / «Закрыть» / «Удалить» / «Отменить» / «Скачать», автосохранение правок, замок смены поставщика, итоги в низу таблицы, добавление по названию и штрихкоду | нет (RPC этапа 25 уже есть) | — |
| 5 | **«Товары поставщика»** | окно с таблицей планирования для выбранного поставщика: категории и подкатегории с «+/−», 8 недель продаж, остаток, запас/дн, спрос/дн, рек., цель, дн, в пути, заказ; сверху дата доставки, страховой запас, «пропускаем визит»; «Добавить в документ». Без цветов нормы и верхней шкалы | возможна RPC выборки по поставщику | самый большой этап: перенос таблицы планирования в окно |
| 6 | **«Добавить из номенклатуры»** | та же таблица по всем товарам снимка UMAG (≈8,6 тыс.), группы свёрнуты, поиск; товары другого поставщика недоступны | нет | в снимке только товары с остатком или продажами; полный справочник UMAG (27,7 тыс.) — отдельный необязательный этап (нужна проверка запроса UMAG) |
| 7 | **Список «Заказы» приёмщика** | тот же вид списка без «+», без черновиков; документ только для чтения с галочками и «Сверено»; «Сегодня ждём N поставок, M товаров» | нет | — |
| 8 | **Переключение и чистка** | меню ведёт на новые страницы; старое «Планирование» снимается, затем удаляются его код, `generate_procurement_orders_from_snapshot`, правка итоговых количеств; кнопка «Обновить данные UMAG» остаётся (в окне «Товары поставщика») | удаление функций и колонок — владелец в SQL Editor | делается после недели работы на новом |

Порядок: 1 → 2 → 3 → 4 → 5 → 6 → 7 → 8. Этапы 1–2 не меняют поведение, этапы 3–7 добавляют новые страницы под отдельными адресами, 8 переключает.

## Решения по умолчанию (поправьте, если не так)
1. Нумерация с **1001**, сквозная, номер выдаётся при «Сохранить» и остаётся после «Отменить».
2. Номенклатура на первом выпуске — снимок UMAG (≈8,6 тыс. товаров), полный справочник — позже отдельно.
3. «Обновить данные UMAG» (синхронизация остатков и продаж) переезжает в окно «Товары поставщика».
