# Статусы заказа — итоговая схема (решение владельца, 2026-10-28)

Заменяет разделы 2–5 из `README.md` (там аудит и первоначальный вариант с отменённым статусом и приёмкой).

## Статусов два

| Статус | Подпись | Кто видит | Смысл |
|---|---|---|---|
| `draft` | Черновик | только закупщик (и роли с правом редактирования) | заказ собирается, приёмщик его не видит |
| `saved` | Сохранён | закупщик и приёмщик | заказ готов, приёмщик сверяет галочками |

«Отменён», «Принят», «Ожидает приёмки», «Сформирован», «Отправлен», «Частично принят» — удаляются. Раздела и статусов приёмки больше нет:
остаются только галочки «сверено» по строкам (хранятся в браузере) и общая отметка «Сверено» на заказе (`checked_at`).

## Что можно сделать

| Статус | Действия | Результат |
|---|---|---|
| Черновик | менять количества, добавлять и удалять позиции, менять дату доставки, комментарий | остаётся черновиком |
| Черновик | **Сохранить** (нельзя пустой заказ и заказ с нулевыми количествами) | → Сохранён |
| Черновик | **Удалить** (безвозвратно, с подтверждением) | запись исчезает; для заказа из «Закупа» количества возвращаются в план |
| Сохранён | **Скачать** (PDF / Excel) | без изменений |
| Сохранён | **Отменить** (с подтверждением) | → Черновик; отметка «Сверено» снимается; заказ пропадает из списка приёмщика |
| Сохранён | править позиции, удалять | **нельзя** — сначала «Отменить» |

Поставщик в заказе не меняется (для другого поставщика — новый заказ).

```
          ┌────────── Сохранить ──────────┐
          │                               ▼
   ┌───────────┐                    ┌────────────┐
   │ ЧЕРНОВИК  │◀──── Отменить ─────│ СОХРАНЁН   │
   │ правки    │                    │ скачать    │
   └───────────┘                    │ сверка     │
          │                         └────────────┘
          └── Удалить навсегда ──▶ (записи нет)
```

## Откуда берётся черновик
- «Закуп» (планирование) → кнопка формирования заказа: **создаёт сразу «Сохранён»**, как сейчас (количества уже подтверждены в плане) — *решение владельца ниже*.
- «Заказы» → «Новый заказ» (вручную) → создаётся «Черновик».
- «Сохранён» → «Отменить» → «Черновик».

## Влияние на остальное
- **План закупок, «В пути»**: считаются только заказы «Сохранён» с датой доставки ≥ сегодня. Черновик не считается (ещё не заказан).
- **Отмена больше не возвращает количества в план** (заказ остаётся как черновик). Возврат в план — только при «Удалить» черновика из «Закупа».
- **Рассчёты с поставщиками** используют поставки UMAG, не приёмку платформы — не затрагиваются.
- **Права**: `receiving.view` («Просмотр заказов») остаётся; правка/сохранение/удаление — `procurement.orders.edit`-аналог (как у отмены сегодня).

## Сервер
Все переходы только через RPC, под блокировкой строки заказа, с проверкой прав:
`procurement_save_order_edit` (черновик), `procurement_submit_order` (черновик → сохранён), `procurement_cancel_order` (сохранён → черновик, переименовать в `procurement_unsave_order`), `procurement_delete_draft_order` (жёсткое удаление + возврат в план).
Прямые записи в таблицы с клиента — запрещены (RLS «simple» политики убрать).

## Миграция старых данных (959 заказов)
- `awaiting_receiving` (771) и `received` (168) → `saved`.
- `cancelled` (20) → удалить (операция `delete`, выполняет владелец в SQL Editor; без CASCADE, одной транзакцией).
- Таблицы приёмки `receiving_documents` (957) и `receiving_items` (10 235) + код, фото, права — удалить отдельным этапом (по образцу stage-13d, preflight с поиском по коду и Edge Functions).
- `workflow_mode` (`simple`/`analytics`) и колонки привязки к плану остаются (нужны для возврата количеств в план), но на права редактирования больше не влияют.
- Ограничение значений статуса — CHECK `status in ('draft','saved')`.

## Этапы (один PR = одно направление)
1. БД: RPC переходов, миграция статусов, CHECK, снятие RLS «simple», чистка отменённых (владелец). `verify:order-statuses`.
2. Интерфейс: две кнопки по таблице, список «Заказы» (приёмщик — только «Сохранён», закупщик — оба), «Новый заказ», подписи, убрать мёртвые статусы из кода.
3. Удаление приёмки: код, таблицы, права, документ этапа с откатом.
