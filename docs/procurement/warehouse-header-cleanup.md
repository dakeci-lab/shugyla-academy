# PR — «Склад»: убрать статус заказа/период из шапки, кнопка Excel — к поиску

## 0. Статус: реализовано, проверено вёрсткой на реальных CSS-классах

## 1. Проблема (запрос владельца)

Шапка снимка склада показывала зелёный бейдж «Заказы частично сформированы»
и «Период: 2026-07-07 — 2026-08-31». Владелец: «Склад» — это просто снимок
остатков на момент синхронизации, информация про генерацию заказов и их
период сюда не относится (это про вкладку «Заказы»). Плюс кнопка «Скачать
Excel» стояла отдельной строкой на всю ширину шапки, оторванно от поиска
под ней — попросили расположить рядом с поиском.

## 2. Решение

`ProcurementWarehouseView.jsx`:

- Убран бейдж статуса (`STATUS_LABELS`/`statusTone`, читали
  `procurement_snapshots.status` — значения `ready`/`syncing`/`failed`/
  `generated`/`partially_generated`) и текст «Период: …» (`formatPeriod`,
  читал `periodFrom`/`periodTo`) из шапки снимка. Сама дата синхронизации
  («Синхронизация от …») осталась.
- «Скачать Excel» перенесена в `actions` пропс `PlatformSearchToolbar` —
  компонент уже поддерживал этот слот (`platform-search-toolbar__actions`,
  тот же flex-ряд, что и инпут поиска), просто раньше не использовался
  здесь.
- Удалены неиспользуемые больше `STATUS_LABELS`, `statusTone()`,
  `formatPeriod()` и мёртвые CSS-правила `.proc-wh__status*`/
  `.proc-wh__detail-period`.

## 3. Verify

```bash
npm run verify:procurement-warehouse-header
```

4 проверки: бейдж/период убраны из шапки, мёртвый CSS убран, заголовок с
датой синхронизации не тронут, кнопка экспорта переехала в `actions`
тулбара поиска.

## 4. Preflight

```bash
npm run build
npm run verify:procurement-warehouse-header
```

Проверено вёрсткой на настоящих CSS-классах компонента (desktop) — шапка
без бейджа/периода, кнопка сразу за полем поиска в одну строку.
