# Сохранение нормы категории — атомарно

Дата: 2026-10-17 · Этап 16c

## Проблема

Норма категории записывалась в **все** товары категории, а затем браузер отдельными запросами по одному возвращал нормы
подкатегорий-исключений. При обрыве связи (или закрытой вкладке) часть подкатегорий в текущем снимке оставалась с нормой
категории до следующей синхронизации — а по нормам считается шкала соответствия запаса.

## Что изменено

- `set_procurement_norm_rule_for_snapshot`: при сохранении нормы категории (подкатегория пустая) обновляются только товары,
  у чьей подкатегории **нет** собственного правила. Всё в одной транзакции. Сигнатура и права не менялись.
- `saveProcurementCategoryNorm` (фронтенд) — один запрос вместо запроса + цикла возврата.
- Журнал (этап 16b) больше не засоряется временными перезаписями.

## Проверено (транзакция с откатом, живые данные)

Категория «Газировка и энергетики»: 197 товаров → 155 получили новую норму, 42 товара подкатегорий-исключений не тронуты.
Категория, где все подкатегории с исключениями: 0 обновлений, 44 из 44 товаров сохранили свою норму.

## Порядок выкладки

Функция в БД применена первой: она совместима со старым фронтендом (старый цикл возврата просто повторяет те же значения).

## Откат

Вернуть предыдущее тело функции (условие `or v_sub = ''` без `not exists`) и предыдущий фронтенд.
