# «Роли и доступы» — CRUD-матрица вместо сайдбара + глобальное обновление палитры

## 0. Статус: реализовано, проверено сборкой + реальным (не мокнутым) юнит-тестом + браузерным mount-тестом на настоящем каталоге прав

## 1. Контекст

Владелец сравнил UI редактирования прав в UMAG (выпадающий список
должности/роли + кнопка «+» рядом, вкладки модулей, таблица-матрица
Смотреть/Создавать/Редактировать/Удалять) с нашим текущим экраном «Роли и
доступы» (отдельный сайдбар со списком ролей, поиском и фильтрами, плоский
список чекбоксов на карточку модуля с описаниями и поиском по разделам) и
попросил сравнить и предложить, перенимать ли структуру UMAG — явно **без
изменения модели данных** (роль остаётся независимой от должности,
`positions`/`position_groups` не трогаются).

Владелец подтвердил направление и попросил сначала прототип: интерактивный
HTML-макет, который можно покликать и дать правки скриншотами, до того как
верстать в реальной платформе. Макет опубликован как Artifact, прошёл 4
раунда правок владельца (убрать хедер-баннер, не завязывать выпадающий
список на карточку сотрудника, убрать поиск/описания/счётчики везде,
починить обрезание длинного названия роли — по образцу macOS truncate, а
не расширение контейнера), и был утверждён как финальный дизайн.

Финальное сообщение владельца объединило два задания:

- **(A)** реализовать утверждённый макет по-настоящему в платформе;
- **(B)** тот же фон/акцентный зелёный/серый текст, что в макете,
  применить **везде** в платформе — не только в разделе ролей.

## 2. Что изменилось — (A) сама структура ролей

**Модель данных не тронута.** `roles`/`permissions`/`role_permissions` и
`positions`/`position_groups` остаются двумя независимыми системами, как и
было (см. `verify-employee-position-role-separation.mjs` — не менялся и по
прежнему зелёный).

**Удалено** (старый сайдбар + toolbar поиска по правам):
`RolesSidebar.jsx`, `RoleListItem.jsx`, `RoleFilters.jsx`, `RoleHeader.jsx`,
`PermissionSearchToolbar.jsx`, `PermissionModuleCard.jsx`, `PermissionItem.jsx`.
Заодно из `teamManagementUtils.js` убраны осиротевшие экспорты
`filterRoles`, `ROLE_FILTERS`, `employeesLabel` — они существовали только
для удалённых компонентов, других вызывающих не было.

**Добавлено:**

- [`RolePickerRow.jsx`](../../src/components/admin/team/RolePickerRow.jsx) —
  один выпадающий список ролей (без поиска — ролей мало, «можно посчитать
  по пальцам», решение владельца) + кнопка «+ Создать роль» +
  `RoleActionsMenu` (переиспользован без изменений) для выбранной роли.
  Неактивные роли остаются в списке (затемнены), ничего не прячется
  безвозвратно, как раньше не прятал и старый фильтр «Неактивные».
- [`PermissionMatrixPanel.jsx`](../../src/components/admin/team/PermissionMatrixPanel.jsx) —
  вкладки модулей (та же горизонтальная подчёркнутая вкладка, что уже
  используется в «Закупках», а не старый стиль скруглённых пилюль) +
  таблица-матрица на активный модуль: одна строка на ресурс, один столбец
  на действие. Использует уже существовавшие в каталоге функции
  `groupPermissionsForMatrix`/`parsePermissionAction`, плюс две новые
  чистые функции в `permissionCatalog.js`:
  - `getPermissionResourceKey(code)` — средний сегмент кода между модулем и
    действием (`umag.reconciliations.resolve` → `reconciliations`;
    `employees.view` → `''`, сам модуль и есть единственный ресурс);
  - `groupModulePermissionsIntoRows(group)` — группирует права модуля по
    ресурсу в строки матрицы.

  Столбцы сортируются не в порядке встречи прав в каталоге, а по
  канонической CRUD-очерёдности: `['view','create','edit','delete','manage']`
  первыми, остальные действия (`sync`, `resolve`, `view_team`, …) —
  следом, в порядке встречи. Без этого модуль UMAG (у которого реально
  есть и `sync`, и `resolve` вперемешку с обычным CRUD) рендерил столбцы в
  случайном на вид порядке.
- `src/components/admin/team/RolesWorkspace.jsx` переписан на новую
  структуру, но **вся существовавшая логика сохранена без изменений**:
  dirty-tracking (`idsEqual`), предупреждение `beforeunload` при
  несохранённых правках, оба диалога подтверждения (переключение роли с
  несохранёнными правками / деактивация роли), защита
  `ADMIN_PROTECTED_PERMISSIONS` (роль администратора не может лишиться
  права управлять ролями/настройками), выбор роли через URL-параметр.

**Найдено и исправлено по ходу** (обнаружено реальным mount-тестом
`PermissionMatrixPanel` на настоящем `PERMISSION_CATALOG`, а не на
придуманных данных прототипа):

1. Действие `resolve` (`umag.reconciliations.resolve`) рендерилось в
   заголовке столбца непереведённым английским текстом — в каталоге не
   было `PERMISSION_ACTION_LABELS.resolve`. Добавлено: `'Закрытие
   расхождений'`.
2. Порядок столбцов был порядком встречи прав в данных, а не CRUD-first —
   см. выше.

**Case, случайно задетый и исправленный до сборки:** удаляя старый
сайдбар, чуть не снёс `.team-role-filters__chip`/`.team-role-item__status`
из CSS как «мёртвые» — но их независимо переиспользуют фильтры и
статус-бейджи вкладок «Организационная структура»
(`PositionsWorkspace.jsx`/`PositionGroupsWorkspace.jsx`, явно вне периметра
этой задачи — владелец: «остальные группы должностей, должностей — они
будут как по-прежнему»). Пойман grep-проверкой перед сборкой, 4 конкретных
правила восстановлены с комментарием.

**Правка после первого прод-деплоя** (владелец проверил вживую,
скриншотом отметил два места): страничный заголовок «Управление командой»
+ подзаголовок-описание над переключателем вкладок убраны полностью
(`TeamManagementPage.jsx`, классы `team-mgmt__title`/`team-mgmt__subtitle`
удалены из CSS — нигде больше не использовались). Переключатель вкладок
«Роли и доступы / Группы должностей / Должности» перестал быть скруглёнными
пилюлями с заливкой — теперь тот же подчёркнутый стиль вкладок, что в
«Закупки» (`.procurement-page__tab`/`.tab.is-active`): прозрачный фон,
нижняя граница 2px у активной вкладки, без заливки и без бордера-пилюли.
Логика переключения вкладок (`TeamManagementTabs.jsx`, `resolveTab`,
подтверждение при несохранённом порядке) не тронута — только разметка/CSS.

Тем же заходом убран счётчик «отмечено/всего» рядом с каждой вкладкой
модуля в самой матрице (`PermissionMatrixPanel.jsx`, было
`{checked}/{total}` справа от названия модуля) и такой же счётчик в
модальном окне создания/дублирования роли (`RoleEditorModal.jsx`, было
`roles-access__module-count` рядом с чекбоксом «выбрать весь модуль») —
владелец: подсказка «сколько из них выбрано» не нужна нигде в этом разделе.
Обе логики выбора (`allChecked`/`indeterminate` для чекбокса «весь модуль»)
не тронуты — убран только видимый текст счётчика.

## 3. Что изменилось — (B) глобальная палитра

Утверждённый в макете набор цветов (более насыщенный изумрудно-зелёный
акцент, более холодный/дорогой фон, серый текст) перенесён в
`:root`-токены `src/index.css`:

| Токен | Было | Стало |
|---|---|---|
| `--color-primary` | `#2a9d5c` | `#059669` |
| `--color-primary-dark` | `#1f7a47` | `#047857` |
| `--color-primary-light` | `#e6f5ec` | `#ecfdf5` |
| `--color-primary-soft` | `rgba(42,157,92,0.12)` | `rgba(5,150,105,0.12)` |
| `--color-bg` | `#f4f6f4` | `#f8fafc` |
| `--color-text` | `#141414` | `#0f172a` |
| `--color-text-secondary` | `#4a524d` | `#64748b` |
| `--color-text-muted` | `#7a857c` | `#94a3b8` |
| `--color-border` | `#dde5df` | `#e2e8f0` |
| тени (`--shadow-sm/md/lg`) | старый чёрный тон | тот же оттенок, что и новый `--color-text` |

Токены применяются каскадно почти везде по архитектуре проекта, но
~30 файлов задавали те же цвета как **литералы** (в основном — fallback
второй частью `var(--color-primary, #059669)`, где сам fallback был
рассинхронизирован со старым значением токена) вместо ссылки на переменную.
Все найденные литералы заменены на новые значения тем же массовым sed по
списку файлов (см. `git diff --stat` для полного списка — в основном
`src/components/admin/**/*.css`, несколько `src/pages/*.css`, и один JS-litreral
в `src/utils/companyHealth.js`).

Не тронуто намеренно: `--color-hero-bg`, `--color-white`, `--color-danger`,
радиусы, высоты хедеров — не входили в замечание владельца о «дороже
выглядящем» фоне/акценте/тексте.

## 4. Verify

```bash
npm run verify:roles-crud-matrix-redesign
npm run build
```

`verify:roles-crud-matrix-redesign` — 45 проверок: старые файлы
действительно удалены и нигде не импортируются; выпадающий список ролей
без поиска/описания; **реальный импорт** `groupModulePermissionsIntoRows`/
`getPermissionResourceKey`/`getPermissionActionLabel` на настоящем
`PERMISSION_CATALOG` (не выдуманных данных) — включая явную проверку CRUD-
порядка столбцов для модуля UMAG; dirty-tracking/save/cancel/оба
confirm-диалога/admin-guard на месте; общие с «Организационная структура»
CSS-классы (`team-role-filters__chip`, `team-role-item__status`) не задеты
и всё ещё используются `PositionsWorkspace`/`PositionGroupsWorkspace`.

Дополнительно, до написания verify-скрипта — ручной браузерный mount-тест
`PermissionMatrixPanel` с настоящим `PERMISSION_CATALOG` (через временный
`__scratch_matrix_test.jsx`, удалён после проверки): подтвердил и находку
бага #1 (непереведённый `resolve`), и после фикса — правильный итоговый
порядок заголовков `Раздел → Смотреть → Создавать → Редактировать →
Синхронизация → Закрытие расхождений`.

Полный проход `RolesWorkspace.jsx` целиком (не изолированной
`PermissionMatrixPanel`) руками в `npm run dev` за авторизацией — не
сделан в этой сессии: локальный дев-режим без `.env.local` работает без
Supabase-сессии, полноценный вход недоступен без реальных креды или
настройки локального Supabase (`npm run supabase:local:bootstrap`).
Компенсировано: сборка чистая, вся сохранённая бизнес-логика
(`useRoleEditor`, guard-функции) не переписывалась — только точки её
монтажа в JSX, и структурная проверка `RolesWorkspace.jsx` подтверждает
корректное подключение всех сохранённых обработчиков.
