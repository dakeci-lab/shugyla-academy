# Фикс — карточка деталей открывается посреди страницы вместо экрана

## 0. Статус: реализовано и подтверждено измерением в браузере (не только по коду)

## 1. Проблема (репорт владельца)

В «К оплате» клик по строке (например, «СПК товары», самая верхняя строка)
не показывал карточку деталей — она открывалась «где-то посреди страницы»,
и чтобы её увидеть, нужно было прокрутить вниз, независимо от того, где был
клик и в какой точке экрана.

## 2. Причина (подтверждена измерением, не только чтением кода)

`GroupDetail` (карточка деталей строки, `SupplierPaymentsPanel.jsx:376`) —
`position: fixed`, но рендерится инлайн, глубоко внутри дерева страницы
(`SupplierFinancePanel` → `SupplierPaymentsPanel` → `GroupDetail`), а не через
React-портал.

Весь контент платформенных страниц обёрнут в `PullToRefresh`
(`src/components/platform/PullToRefresh.jsx:157`), у обёртки которого
(`.pull-to-refresh__body`) в CSS стоит `will-change: transform`
**постоянно** — не только во время реального перетягивания
(`PullToRefresh.css:15`).

По спецификации CSS `will-change: transform` создаёт для `position: fixed`
потомков новый containing block — так же, как настоящий `transform`.
Поэтому «fixed» карточка на самом деле позиционируется не относительно окна
браузера, а относительно этой обёртки, которая по высоте равна **всей
странице**. `align-items: center` центрирует её не в видимой области, а в
середине всей прокручиваемой страницы.

**Подтверждено измерением**, не только рассуждением: собрал минимальную
HTML-репродукцию той же структуры (`will-change: transform` на обёртке +
вложенный `position: fixed`-потомок против такого же элемента-портала на
уровне `body`) и снял `getBoundingClientRect()` при `scrollY: 0`,
`innerHeight: 841`:

| | top |
|---|---|
| инлайн (внутри `will-change`-обёртки) | **1472.5px** — далеко за пределами экрана |
| портал (в `document.body`) | **393px** — ровно по центру экрана |

Это тот же баг, что и в предыдущем PR про «Расчёты»: `AdminModal.jsx` уже
решает его правильно через `createPortal(..., document.body)` — модалки на
его основе (например, «Создать акт сверки») не ломаются. Такая же проблема
была и в `OperationDetailSheet.jsx` (Взаиморасчёты → клик на поставщика →
клик на операцию) — найдено в ходе этого же разбора, ещё не зарепорчено
владельцем, но сломалось бы точно так же при первом клике.

## 3. Решение

`SupplierPaymentsPanel.jsx` (`GroupDetail`) и `OperationDetailSheet.jsx` —
оба теперь `return createPortal(<...>, document.body)`, по образцу
`AdminModal.jsx`. Только точка рендера; ни разметка, ни `role="dialog"`/
`aria-modal`/`aria-label`, ни логика клика не менялись.

Не тронуто (сознательно, не входило в репорт): блокировка скролла страницы
и закрытие по Escape, которые уже есть у `AdminModal`, здесь так и остаются
отсутствующими — это отдельное UX-улучшение, не эта позиционная ошибка.

## 4. Verify

```bash
npm run verify:supplier-finance-detail-sheets-portal
```

5 проверок: причина (`will-change: transform` действительно ещё стоит),
существующий эталонный паттерн (`AdminModal`), обе карточки используют
`createPortal(..., document.body)`, разметка/aria не менялась.
