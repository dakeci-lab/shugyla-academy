# Фикс — изменение срока оплаты поставщика не обновляло уже открытые долги

## 0. Статус: реализовано, подтверждено реальным (не мокнутым) юнит-тестом на точном сценарии из репорта

## 1. Проблема (репорт владельца)

Поставщик «Тассай»: приёмка от 26.08.2026 создала долг при условиях оплаты
«0 дней» (в тот момент так стояло в карточке). После этого карточку
отредактировали — поставили «14 дней». Но в «К оплате» эта же приёмка
по-прежнему показывала «Отсрочка — 0 дн.» и была просрочена по старому
сроку. Тост после сохранения карточки утверждает «Сроки обязательств
обновлены» — но фактически не обновляет ничего для уже существующих
приёмок.

## 2. Причина

`supplier_payment_obligations.due_date` — «снимок», который по комментарию
в миграции объявлен **«Immutable after first set»**. Нигде в коде не
объяснено, зачем это нужно как бизнес-правило (не «не менять задним числом
уже согласованный срок» — просто так реализовано).

Единственная функция, которая пишет этот снимок из UI-потока —
`applyMissingObligationSnapshotsForSupplier` (`supplierPaymentObligationsService.js`),
вызывалась после сохранения карточки поставщика. Но её фильтр — `.is('due_date', null)`:
она заполняет только те приёмки, у которых срок ещё никогда не был
посчитан. Если срок уже стоит (даже неверный/устаревший) — функция эту
строку пропускает молча, навсегда.

Синхронизация с UMAG (`umag-sync/index.ts`) устроена так же: гард
`hasSnapshot = due_date != null || terms_snapshot_created_at != null`
специально не даёт пересчитать уже заснапшоченную строку ни при каком
повторном ↻ — то есть повторная синхронизация тоже не помогла бы.

## 3. Решение

Функция переименована и переписана: `refreshObligationTermsForSupplier`
(`supplierPaymentObligationsService.js`) — вызывается там же, после
сохранения карточки поставщика, но теперь:

- Берёт **все открытые** обязательства этого поставщика
  (`is_source_deleted = false AND current_debt > 0`) — тот же периметр,
  который уже используется в других местах кода (частичный индекс
  `idx_spo_active_due`, фильтр `listPaymentObligations`), а не только те, у
  кого срок пуст.
- Для каждой сверяет текущий снимок с тем, что должно быть при АКТУАЛЬНЫХ
  условиях поставщика — через новую чистую функцию
  `resolveObligationTermsPatch()` (`supplierPaymentObligations.js`).
  Пишет только если реально отличается — идемпотентно, не дёргает
  `terms_snapshot_created_at` зря при несвязанных правках карточки.
- Симметрично: если поле «Срок оплаты» у поставщика очистили совсем
  («не настроено»), уже открытые обязательства тоже сбрасываются в
  `due_date: null` — та же логика, тот же единственный источник правды.
- Оплаченные/удалённые из UMAG строки (`current_debt <= 0` или
  `is_source_deleted = true`) никогда не трогаются — это исторический
  остаток, не расписание.

**`umag-sync` (Edge Function) не тронут.** Он общий на всех поставщиков и
на каждый клик синхронизации — менять его гард рискованнее (задело бы
вообще всё), и не нужно: клиентского пути через сохранение карточки
достаточно, а после пересчёта `due_date` синхронизация просто увидит
`hasSnapshot = true` с уже верным значением и не станет его трогать.

## 4. Verify

```bash
npm run verify:supplier-retroactive-payment-terms
```

7 проверок, включая **реальный (не мокнутый) прогон точного сценария из
репорта** через настоящий импорт `resolveObligationTermsPatch` +
`resolveSupplierPaymentTerms`:

```
cash/0 дней, приёмка 26.08 → меняем условия на deferral/14
→ due_date пересчитан в 2026-09-09
```

Плюс: идемпотентность (повторный вызов при неизменных условиях не пишет
ничего), симметричный сброс при очистке срока, отсутствие выдуманного
`due_date` без даты документа, структурные проверки сервисного слоя и
вызывающего кода.

`refreshObligationTermsForSupplier` сама по себе (сетевые вызовы Supabase)
не прогонялась вживую — нет `.env.local` в этой среде. Чистая функция
принятия решения (`resolveObligationTermsPatch`) — сердце фикса — прогнана
по-настоящему.

```bash
npm run build

npm run verify:supplier-payments
```

**Нужно подтвердить на живых данных:** открыть карточку «Тассай», убедиться,
что «Срок оплаты» уже 14, пересохранить карточку (можно без изменений —
теперь функция вызывается на каждое сохранение, идемпотентно), проверить,
что в «К оплате» приёмка от 26.08 стала показывать «Отсрочка — 14 дн.» и
пересчитанный срок.

## 6. Критерии приёмки

- [ ] Изменение срока оплаты поставщика и сохранение карточки обновляет
      `due_date` у всех его текущих открытых долгов, не только у новых.
- [ ] Оплаченные/удалённые из UMAG обязательства не меняются никогда.
- [ ] Повторное сохранение карточки без изменения срока не производит
      лишних записей в БД.
- [ ] Очистка срока («не настроено») возвращает открытые долги этого
      поставщика в баннер «Без срока».
