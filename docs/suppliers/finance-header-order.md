# PR — «Расчёты»: вкладки выше KPI, KPI только на «К оплате»

## 0. Статус: реализовано, ждёт клика в реальном UI (в дев-окружении логина нет)

## 1. Проблема

Владелец продукта: при открытии «Расчёты» сначала должны быть видны сами
вкладки (К оплате / Взаиморасчёты), а сводные плитки (Долг/Просрочено/
Сегодня/Оплачено) — под ними, и только для вкладки «К оплате». Раньше плитки
стояли первыми и показывались одинаково на обеих вкладках.

## 2. Почему это правильно (по коду)

Плитки KPI считаются из `fetchSupplierFinancePageData()` →
`supplier_payment_obligations` — тех же данных, что и очередь «К оплате».
«Взаиморасчёты» эту сводку не использует вообще (сам тянет итоги через
`fetchUmagSettlementsBySupplier`). Показывать KPI «К оплате» поверх
«Взаиморасчёты» было не про эту вкладку — привязка к активной вкладке точнее
отражает, откуда цифры.

## 3. Изменение

`src/components/suppliers/finance/SupplierFinancePanel.jsx`:

- Порядок: заголовок → `.sfp-panel__bar` (вкладки + статус синхронизации) →
  KPI-плитки (и их баннер ошибки загрузки) → контент активной вкладки.
- Новый флаг `showKpis = canViewPayments && activeTabMeta?.id === 'payments'`
  гейтит и плитки, и баннер ошибки — раньше их единственным условием было
  `canViewPayments`, то есть они держались видимыми на обеих вкладках.
- CSS (`SupplierFinancePanel.css`) не тронут — `.sfp-panel` уже flex-column с
  `gap`, порядок детей не завязан на соседние селекторы.
