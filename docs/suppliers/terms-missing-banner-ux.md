# PR — «Без срока» перестаёт быть вкладкой очереди по срокам (Расчёты, шаг 1/4)

## 0. Статус: реализовано, ждёт проверки владельцем в реальном UI (в дев-окружении логина нет)

## 1. Проблема

Раздел «Расчёты» (`/platform/supplier-finance`) — точка входа №1 для ежедневной
работы с долгами поставщикам. Владелец продукта отметил, что вкладка
«К оплате» ощущается нелогичной: рядом с приоритетными по времени группами
(Просрочено / Сегодня / Предстоящие) стоит «Без срока» — как будто это тоже
про срочность оплаты, хотя на деле это сигнал «у поставщика не настроены
условия оплаты» — задача из другой плоскости (конфигурация карточки
поставщика), не про то, когда платить.

Это первый шаг из согласованной серии небольших PR по разделу «Расчёты»:

1. **(этот PR)** «Без срока» → баннер-предупреждение, а не секция очереди.
2. Явная подпись «Итого за период/поиск» под таблицей «Взаиморасчёты», чтобы
   не читалось как дубль KPI «Долг» (см. п.2 ниже — почему это не дубль).
3. Аффорданс клика по строке во «Взаиморасчётах» (сейчас понятно только по
   цвету текста, что это ссылка на акт сверки).
4. Кросс-ссылки поставщик ↔ его обязательства между двумя вкладками.

## 2. Что происходит на самом деле (по коду)

- `buildPaymentScheduleView()` (`src/utils/supplierPaymentObligations.js:135`)
  уже отдаёт `lists.termsMissing` и `summaries.termsMissing` отдельно от
  `overdue/today/upcoming` — данные и так разделены, смешение было только в
  презентационном слое.
- Встроенный (embedded) рендер «К оплате» внутри общей оболочки «Расчёты» —
  `CompactPaymentSchedule` в
  `src/components/suppliers/payments/SupplierPaymentsPanel.jsx` — до этого PR
  просто маппил `COMPACT_SECTIONS` (4 записи, включая `termsMissing`) в
  одинаковые `<section>` с одинаковым визуальным весом.
- Отдельная проверка по коду (см. п.3): footer «По списку» под таблицей
  «Взаиморасчёты» (`UmagSettlementsPanel.jsx`) — **не дубль** KPI «Долг».
  Он считается через `fetchUmagSettlementsBySupplier({ dateFrom, dateTo, search })`,
  т.е. это итог по выбранному периоду/поиску, а не глобальный долг. Совпадает
  с KPI только потому что период по умолчанию — «месяц», и весь долг попал
  туда. Трогать в этом PR не стал — вынес в шаг 2 отдельной подписью, а не
  удалением.
- Единственный маршрут, из которого раздел реально достижим —
  `/platform/supplier-finance` (в `platformNav.js`, label «Расчёты»).
  Старые `/platform/settlements` и `/platform/supplier-payments` в App.jsx
  ещё существуют, но из навигации убраны — значит некомпактный (карточки +
  вкладки-пилюли) рендер `SupplierPaymentsPanel` живыми пользователями не
  используется. Правки в этом PR — только в `embedded`-ветке
  (`CompactPaymentSchedule`), некомпактная ветка не тронута.

## 3. Принятые решения

- «Без срока» выносится из `COMPACT_SECTIONS` и рендерится отдельным
  компонентом `MissingTermsBanner` **над** очередью по срокам — сворачиваемый
  баннер тёплого (жёлтого/warning) цвета, а не таблица с тем же оформлением,
  что и Просрочено/Сегодня/Предстоящие.
- По умолчанию свёрнут: строка «N поставщиков без срока оплаты — настройте
  условия · сумма» + шеврон. Разворачивается по клику — показывает те же
  строки поставщиков с кнопкой «Настроить отсрочку» (переиспользуется
  существующий `CompactObligationRow`, логика клика/перехода не менялась).
- Число в баннере — количество **поставщиков** (`filteredMissingGroups.length`),
  а не количество приёмок (как было в заголовке старой секции) — это ближе к
  действию, которое просят совершить: настроить N карточек поставщиков.
- Поиск по поставщику (`PlatformSearchToolbar`) продолжает фильтровать и
  баннер: если совпадений нет — баннер не показывается вовсе.
- Пустое состояние «Нет обязательств к оплате» показывается только когда
  пусты **и** очередь по срокам, **и** список без срока — раньше оно
  ошибочно не учитывало это разделение.

## 4. Что не менялось

- `buildPaymentScheduleView`, `pickDefaultPaymentTab`, некомпактная
  (standalone) ветка `SupplierPaymentsPanel` — без изменений.
- Никаких миграций, RLS, Edge Functions — чистый frontend в одном файле +
  его CSS.

## 5. Verify-скрипт

```bash
npm run verify:supplier-finance-terms-missing-banner
```

8 структурных/логических проверок: `COMPACT_SECTIONS` без `termsMissing`,
`MissingTermsBanner` переиспользует `lists/summaries.termsMissing` без новой
формы данных, баннер рендерится до очереди, свёрнут по умолчанию с
`aria-expanded`, сохранена кнопка «Настроить отсрочку», пустое состояние
учитывает обе группы, CSS не ломает мобильную раскладку строк, чистая функция
`buildPaymentScheduleView` не тронута.

Побочно обнаружено: `npm run verify:supplier-finance-compact-payments`
(Этап 2.8) уже не проходит на `main` **до** этого PR — тесты писались под
более раннюю версию JSX (regex ищёт `<CompactPaymentSchedule` сразу после
`embedded ? (`, а туда с тех пор добавился `PlatformSearchToolbar`). Не мой
регресс, чинить не стал — не в рамках этого PR (одно направление); стоит
почистить отдельной задачей.

## 6. Preflight перед публикацией

```bash
npm run build
npm run verify:supplier-finance-terms-missing-banner
```

Визуально не прогнано в реальном UI — платформа за логином, тестовых
креденшелов в этой сессии нет. Проверено CSS-макетом на реальных классах
(`SupplierPaymentsPanel.css`) с фикстурными данными на desktop и mobile
(375px) через дев-сервер — баннер визуально отделён от очереди, сворачивается,
не ломает мобильную раскладку строк. **Нужно подтвердить кликом в
`npm run dev` с реальным логином до мержа.**

## 7. Критерии приёмки

- [ ] «Без срока» не отображается как секция среди Просрочено/Сегодня/Предстоящие.
- [ ] Баннер свёрнут по умолчанию, показывает число поставщиков и сумму.
- [ ] Разворачивается по клику, показывает список с «Настроить отсрочку».
- [ ] Поиск по поставщику фильтрует и баннер.
- [ ] Пустая очередь без «без срока» и наоборот — каждое состояние выглядит
      корректно (баннер/секции скрываются независимо).
- [ ] `npm run build` и verify-скрипт зелёные.
